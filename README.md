## 실행

이 폴더에서 다음 명령을 실행하고 http://127.0.0.1:8766 을 연다.

```powershell
python -m http.server 8766 --bind 127.0.0.1
```

빌드나 API 키가 필요 없다. 파일 경로는 상대 경로이며 GitHub Pages의 프로젝트 경로에서도 사용할 수 있다. HTML·CSS·JavaScript와 출처가 표시된 자료만 제공하는 정적 사이트다.

## 공개 호스팅과 수정

공개 저장소는 [gisbi-kim/jev-decision-atlas](https://github.com/gisbi-kim/jev-decision-atlas)이며 GitHub Pages의 게시 소스는 `main` 브랜치의 루트(`/`)다. `.nojekyll`을 포함해 정적 파일을 그대로 제공한다. 이후 `main`에 반영한 변경은 Pages에서 다시 게시된다.

글은 `articles.js`, 입문은 `intro.js`, 포켓몬 로컬 실행 추가분은 `pokemon-local.js`에서 수정한다. 수정한 뒤 다음 검사를 실행한다. Node.js 24에서 확인했다.

```sh
node scripts/check-content.cjs
node scripts/export-diagrams.cjs
```

첫 명령이 만드는 `validation.json`은 검사 결과이며 Git에는 포함하지 않는다. 다이어그램을 바꾸었다면 두 번째 명령으로 갱신한 `diagrams/` 파일을 함께 반영한다.

## 포켓몬 로컬 실행 기록

포켓몬 글의 10~14절은 강의자가 제공한 실행 기록이다. `christianmat/jev-pokemon`의 Jev 백엔드를 Ollama `qwen3.5:9b`로 교체하고 RTX 5070 Ti Laptop에서 실행한 사례로 설명한다. 기존 Jev 원작의 결과와 로컬 실행의 관측을 구분한다.

- `pokemon-local.js`: 저장·기억·문맥 구성·전투·이동 다섯 절을 기존 포켓몬 글에 추가한다.
- `assets/pokemon-local/`: 첨부에서 추출한 system 메시지, 전투와 이동의 입력·출력, 저장 구조와 기억 예시 등 9개 원문 파일과 출처·해시 목록을 보관한다.
- 전투 입력 1,187토큰, 이동 요청 923번의 입력 1,354토큰과 응답 864ms는 제공된 개별 기록의 값이다.
- 메모리 원문은 제공된 출력이 끊긴 곳에서 그대로 끝난다. 이동 요청에 제시되지 않은 응답 스키마도 만들지 않았다.
- 긴 JSON은 화면 폭에 맞추어 줄을 감싸고 블록 내부에서 스크롤한다. 복사는 원문의 줄바꿈과 내용 전체를 유지한다.

검증 스크립트는 본문의 9개 기록과 원문 파일의 일치, 파일 해시, JSON 구문, 응답이 후보에 포함되는지, 전투 선택이 다음 이동 문맥의 행동 기록에 나타나는지를 확인한다.
